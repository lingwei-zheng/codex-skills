# Peer Review Report Structure

Use this file when triaging issues, selecting an editorial recommendation, or
drafting working and journal-submission-ready reports.

## Default Issue Hierarchy

1. **Critical revision**: exactly one issue. Select the single highest-risk
   problem that could plausibly cause rejection. Do not bundle unrelated concerns.
2. **Important revisions**: one to five issues affecting theory, logic, methods,
   evidence, statistics, interpretation, reproducibility, or journal fit.
3. **Minor revisions**: one to five issues involving language, terminology,
   formatting, captions, repetition, or presentation.

Follow different counts when the user or journal supplies a template.

## Recommended Files

Place outputs in the manuscript folder unless the user specifies another path.
Create only the files needed for the task:

- `中文审稿报告.md`: Simplified Chinese working report.
- `English_Peer_Review_Report.md`: English working report synchronized with the
  Chinese report.
- `期刊提交审稿意见.md`: concise English journal-submission-ready report.

The Chinese and English working reports must express the same material findings
and recommendation. Translation must not change issue severity.

## Journal-Submission-Ready Report

Open with one paragraph summarizing the study, strengths, main weakness, and
recommendation. Then use only:

- `## 1. Critical Revision`
- `## 2. Important Revisions`
- `## 3. Minor Revisions`

Do not add subheadings for individual points. Write in natural referee-report
prose rather than checklist fragments. Keep the tone firm, specific,
evidence-linked, and constructive.

Each substantive issue should identify:

1. the manuscript claim or component at risk
2. its location: page, section, paragraph, figure, table, equation, or supplement
3. why it matters for validity or interpretation
4. the evidence supporting the concern and whether it is observed, inferred, or
   unavailable for verification
5. a feasible repair or the reason it is not repairable

Critical and important issues must include a location and evidence pointer. If
the source format prevents precise pagination or paragraph identification, use
the narrowest available section, quotation fragment, figure, table, or
supplement pointer and disclose the limitation.

## Recommendation Standard

- **Major Revision**: the paper is promising and plausibly repairable, but a core
  method, evidence-chain, interpretation, or robustness problem remains.
- **Reject**: the contribution is unsupported, the decisive problem cannot be
  repaired with available data, the paper is outside scope, or the method is
  invalid in a way ordinary revision cannot resolve.
- **Minor Revision**: methods and evidence are sound and remaining issues are
  principally clarification, framing, or presentation.

Do not recommend rejection merely because revision is substantial. Do not use
major revision to avoid naming an unfixable validity failure.

## Final Report Check

- State which manuscript and supplementary files were reviewed.
- Confirm visual inspection, or disclose the exact missing visual check.
- Keep exactly one critical issue unless the user specifies another structure.
- Respect important and minor issue limits.
- Use no per-point subheadings in the submission-ready report.
- Keep claims synchronized across language versions.
- Apply all five geography publication-readiness gates when relevant.
- Bind every critical and important issue to a location and evidence pointer.
- Do not overwrite an existing user-edited report without explicit permission.
